The phone bridge, drawn from its code

An old Android phone is a robot's face, eyes and ears. It runs a web page; the atl_phone bridge, a ROS 2 node in Docker, serves that page and maps its WebSocket to topics under /<robot>/phone/ (contract atl-phone/0.2). The brain stays on the PC. These seven diagrams show how a phone gets connected and tested, what the bridge remembers, where it can go wrong, and the Desk Guardian: a ROS 2 node that knows only topics and runs the same against a mock phone, the Thymio twin in Webots, and the real phone.

Every box cites the lines it comes from, at commit a259a7a; the build checked each citation against that commit.

Review findings

FindingEvidenceStatus
After a takeover, a frame the old phone had sent before the close was still parsed and credited to the new phone (on_text did not know which link a message came from), so a late hello could overwrite the new phone's model. Now deliver() passes a frame on only while its link is current, under the same lock as the takeover. A test reproduces the race. wsserver.py 161–180, 283–286 · 05 fixed in 6b29b5a
Output tests (face, gaze, colour, say, torch, vibrate) answered 204 even with no phone, because out() ignores the result of server.send. It misled the first real-phone test (a Galaxy A50): the phone was on the check page while its outputs were tried. act() now refuses them with "no phone", and step 4 shows whether a phone is connected. bridge_node.py 202–216 · 03 fixed in d2b04ac
Between a disconnect and the next phone, /api/state still shows the old senses: closed() clears the phone, not seen. The setup page relies on connected, and keeps what passed once, so its marks stay right. bridge_node.py 113–122, setup.js 404–420 · 04 by design
A check report was matched to the connected phone by model text only. Two phones of a kind looked the same, and the first real phone did not match itself: its hello named it SM-A505FN (client hints), its report "Android 10 phone" (the user agent says K), so the page fell back to the latest report of any phone. Now the face and check pages keep a random id in the browser and both messages carry it. face.js 147–156, bridge_node.py 244–252, setup.js 247–253 · 02 fixed in 9861131
The state dicts are shared between threads without a lock. A stress test (200 000 json.dumps of a dict while another thread adds keys, Python 3.12.3 in the image) raised no error; the bridge replaces values, it does not mutate them in place. bridge_node.py 138–200 · 02 checked · no issue
A phone on plain http over Wi-Fi gets no camera, motion, compass or battery; it now says so in its hello and the setup page marks them blocked, with the fix (USB, or --cert). face.js 157–162, setup.js 415–420 · 01 handled in e8570a6
Wi-Fi with camera and motion needs HTTPS. ./start.sh --make-cert makes this PC's own certificate authority once; the bridge offers /ca.crt and each phone installs it once. The authority's key is not mounted into the container. A phone that has the authority installed trusts anything this PC's key signs, so the setup page says how to remove it when a phone leaves the class. scripts/make_cert.sh, start.sh 68–77, wsserver.py 199–210 · 01 added in d2b04ac
Telling faces apart ("familiar") is a signature kept in the phone's page only. A program can ask for it but not allow it: the facilitator does (familiar:=true or the setup page), and until then the bridge sets every face's number to null, whatever the phone sends. The contract check sends a number and a 128-number descriptor and sees neither reach ROS. bridge_node.py 95–104, 178–185, protocol.py 101–112 · 02 by design
The phone reuses face numbers once it forgets its signatures (familiar off, page reloaded). The guardian kept number 1 as its friend, so a second run of its story greeted a new face as the owner. It now forgets its friends when the bridge's status shows the phone forgot. guardian_node.py 74–80, guardian.py 117–120 · 06 fixed in a259a7a
The guardian, in the bridge's container, heard nothing from atl-bot-thymio's: Fast DDS uses shared memory between processes on one host, and containers do not share /dev/shm. start.sh now makes it use UDP. start.sh 78–80 · 07 fixed in a259a7a
Both ground sensors over nothing count as lifted, so a Thymio that reaches the desk's edge head-on stops and asks to be put down instead of backing off (atl-bot-thymio's behaviours read it the same way). Safe, but not the cliff reaction. The guardian itself never drives forward, so it reaches an edge only by turning. guardian.py 87–101 · 06 open · minor
While the robot is lifted or backing off from the edge, a long touch is not kept for later: petting during those 2.2 s is lost. guardian.py 152–176 · 06 open · minor
